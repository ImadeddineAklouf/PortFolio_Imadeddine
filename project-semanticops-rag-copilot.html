01. Contexte

Le problème traité.

Un modèle de langage ne connaît ni vos documents ni vos données internes, et il peut inventer une réponse plausible.

Le projet applique le principe du RAG : retrouver d'abord les passages utiles dans une base documentaire, puis demander au modèle de répondre seulement à partir de ces passages.

Problème

Des réponses sans source fiable

Sans contexte, un LLM répond de mémoire et peut halluciner.

Solution

Un pipeline de recherche et de génération

Les documents sont indexés, retrouvés par le sens, puis fournis au modèle comme seul contexte.

02. Objectifs

Ce que la plateforme doit accomplir.

01

Ingérer des documents

Charger plusieurs formats et les découper en passages exploitables.

02

Retrouver par le sens

Rapprocher une question reformulée du bon passage, y compris en français.

03

Répondre depuis le contexte

Limiter la réponse aux passages retrouvés et signaler l'absence d'information.

04

Rester testable

Valider le pipeline hors ligne, sans appel réseau ni quota.

07. Démonstration

Lancer le projet.

Uvicorn expose l'API et sa documentation interactive. Une clé Groq est nécessaire pour l'endpoint de question.

# Installer
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Configurer GROQ_API_KEY dans .env
# puis lancer l'API
python -m uvicorn app.api.main:app --reload

# Swagger
http://127.0.0.1:8000/docs
